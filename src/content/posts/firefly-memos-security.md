Memos 内容来自外部服务，即使实例属于自己，也不应该把返回的文本直接当作可信 HTML。Firefly 的动态页和侧栏共用同一套适配器，因此安全边界应放在 `src/utils/memos-adapter.ts`，而不是分别在两个组件里补丁式处理。

本文记录的是启用前的安全改造。当前 `src/config/dynamicConfig.ts` 没有 `memos` 配置块，因此不会打开 Memos，网站继续使用本地动态；在真实实例和浏览器回归完成前，本文只作为安全边界记录，不是上线启用指南。

## Memos 是什么，开和不开有什么区别

Memos 是一个可以自己部署的轻量笔记/动态服务。你在 Memos 后台发布内容后，博客可以通过 API 读取公开动态，把它们显示在动态页或侧栏。它不是 Firefly 必须依赖的数据库，也不是评论系统。

当前项目的两种状态可以这样理解：

| 状态 | 数据从哪里来 | 优点 | 代价 |
| --- | --- | --- | --- |
| Memos 关闭（当前状态） | 仓库构建出的本地 `/api/dynamic.json` | 不依赖第三方实例，页面更稳定，隐私边界更简单 | 新动态需要修改仓库并重新构建部署 |
| Memos 开启 | 你自己的 HTTPS Memos API | 可在 Memos 后台发布，博客自动读取公开动态 | 依赖实例、版本、CORS 和 API 语义；外部请求失败时只能降级 |

本教程完成的是适配器安全加固，不是打开开关。没有真实 Memos 实例、版本和浏览器联调证据前，继续关闭是有意的安全选择。

## 小白跟做步骤

如果你的目标只是“先让博客正常运行”，不要开启 Memos：确认 `src/config/dynamicConfig.ts` 使用 `apiUrl: "/api/dynamic.json"`，然后运行 `pnpm check`、`pnpm type-check` 和 `pnpm build`。

如果你要复刻安全改造，请按以下顺序操作：

1. 备份项目或新建分支，依赖未安装时先运行 `pnpm install`；
2. 打开 `src/utils/memos-adapter.ts`，保留文本转义、链接/图片来源限制、分页/响应体/超时限制和并发去重；
3. 打开 `src/config/dynamicConfig.ts`，先不要填写真实实例地址，也不要把 Token 写到前端配置；
4. 运行 Memos 专项测试，再运行 `pnpm check`、`pnpm type-check` 和 `pnpm build`；
5. 只有在拥有自己的实例并完成版本、`parent` 过滤、CORS、动态页和侧栏浏览器联调后，才另开一个启用计划。

不要把第三方教程中的实例 URL、用户 ID、访问令牌或旧版字段直接复制到自己的仓库。

## 一、先把远端内容变成受控输出

详情页需要把动态内容放进 `innerHTML`，所以不能把 Memos 的 Markdown 或 HTML 原样交给浏览器。`markdownToHtml` 采用简单的固定转换流程：

1. 先移除 Markdown 图片语法，图片交给独立的来源校验流程处理；
2. 单独检查 Markdown 链接的目标，只允许 `http:`、`https:`、`mailto:` 和受控相对地址，并拒绝会被浏览器规范化为外站地址的反斜杠变体；
3. 把其余文本完整 HTML 转义，使 `<script>`、事件属性、内联样式和 iframe 只能作为普通文字出现；
4. 最后只生成标题、强调、代码、列表、引用、分隔线和链接等固定标签。

这样做的重点不是“猜测哪些 HTML 标签安全”，而是远端内容不负责生成 HTML 标签，标签只能由本地代码按白名单产生。

## 二、图片要单独限制来源

图片不是普通文字。`extractImages` 会重新解析 Markdown 图片和 Memos 附件，只接受 HTTPS、与配置的 Memos 实例同源且在实例路径范围内的 URL，同时拒绝凭据、控制字符和路径穿越。附件 ID 与文件名会经过 URL 编码。

这意味着外站图片、HTTP 图片或异常附件会被主动丢弃。旧动态如果依赖外部图床，需要在启用前先核对；安全策略不能为了“尽量显示图片”而放宽到任意外部地址。

## 三、限制请求和响应规模

`fetchMemos` 对实例地址、分页、条目数、响应体、字段长度、附件数量和请求时间都设有上限：默认超时 3 秒，最多 10 秒；默认最多 5 页、300 条动态；正常响应体最多 1 MiB，非 2xx 响应体最多读取 16 KiB，且都通过流式读取在超限时取消。没有可安全读取的 `Response.body` 时，适配器会拒绝解析而不调用无界的 `response.text()`。调用方取消请求时，适配器会传递取消信号；没有调用方信号的同配置并发调用会共享进行中的请求，成功或失败后都会清理去重项，下一次调用可以重新请求。

请求使用 `credentials: "omit"`、`redirect: "error"` 和 `referrerPolicy: "no-referrer"`。非 2xx 响应只记录状态码，不把远端错误正文写入浏览器控制台，避免把实例内部路径或其他敏感信息暴露给访客。

## 四、当前配置仍然关闭

这次改造不会自动启用 Memos，也不需要令牌。当前保持本地动态：

```ts
// src/config/dynamicConfig.ts
// 未配置 memos，继续使用 /api/dynamic.json
```

未来评估启用时，至少要先确认真实实例的 HTTPS 地址、Memos 版本、CORS 行为、`parent` 过滤语义、动态页和侧栏渲染，以及超时/错误/Swup 切换后的清理行为。令牌不能放在客户端。

## 五、验证结果与边界

本轮 Memos 适配器专项测试 **27/27 通过**，覆盖 Markdown 转义、危险链接、同源图片、路径穿越、响应结构、公开状态过滤、分页和规模限制、正常/错误响应体上限、无响应体兼容边界、超时、调用方取消、并发去重与成功/失败清理，以及非 2xx 日志不泄露响应正文。全量测试 **136/136 通过**；`pnpm check` 检查 **228 个文件且为 0 errors、0 warnings、0 hints**，`pnpm type-check` 和 `pnpm build` 通过；生产构建生成 **47 个页面**，Pagefind 索引 **29 个页面**。

### 改完后应该看到什么

- 保持关闭时，首页和 `/dynamic/` 继续使用本地动态；Network 面板只应看到本站的 `/api/dynamic.json`，不应请求 Memos 域名。
- 适配器专项测试通过时，恶意 HTML、`javascript:` 链接、外站图片和超大响应都应被拒绝或降级，不应进入页面执行。
- 即使未来 Memos 实例不可用，动态卡片也只能进入错误/空状态，不能阻塞文章、搜索或构建。

启用 Memos 后的验收还必须额外确认：Memos API 返回公开正常状态的动态、页面没有 CORS 错误、动态页和侧栏都使用同一数据源，并且没有任何浏览器可见 Token。缺少其中一项，就应恢复 `apiUrl: "/api/dynamic.json"`。

这些证据证明当前安全边界在本地代码层面成立，不等于任何 Memos 实例都已经兼容。项目目前没有可用于验收的真实实例，因此浏览器端 Memos 仍未上线；本文公开记录安全改造，但不提供未经联调的启用承诺。

## 六、性能与回滚

没有新增运行时依赖，也没有构建期远端请求。Memos 关闭时不会新增请求；即使未来开启，请求去重、分页上限、响应体上限和图片数量上限也会控制额外开销。去重表只保存进行中的 Promise，成功或失败后都会清理；没有贸然加入成功缓存，以免在没有明确新鲜度需求时显示过期动态。

遇到问题时，删除 `dynamicConfig.memos` 配置块，或把它的 `enable` 设为 `false`，继续使用 `/api/dynamic.json`。不要为了恢复页面而重新启用未经清洗的远端 HTML，也不要把访问令牌写入前端配置。
